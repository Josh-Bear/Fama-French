## บทสรุป 5 บรรทัด
1. **N3 แย่เพราะ "3 กอง = 1 เดิมพัน" บ่อยมาก** (อ่านจาก `M018_weights.csv` เอง): 2022-03 ถือกองเวียดนาม 3 กอง · 2022-06/09/12 ถือ infra โลก 3 กอง (คู่เหล่านี้ ρ_adj 0.996–1.000 ใน log ของ M010) · 2024-09 อินเดีย 3 กอง · 2024-03/06 และ 2025-06 ซ้ำธีม 2 ใน 3 — ปัญหาไม่ใช่ "3 น้อยไป" อย่างเดียว แต่คือ **3 ตัวแรกของ momentum มักเป็นธีมเดียว**
2. **วิธีอันดับ 1 — "Anchor + เติมแบบ min-max ρ_adj จาก pool อันดับ ≤ K"**: กองถือต่อ (อันดับ ≤ 6) คงไว้ · ถ้าไม่มีกองถือต่อ เริ่มจากอันดับ 1 · เติมทีละกองด้วยกองใน top-6 ที่ **ρ_adj สูงสุดกับกองที่เลือกแล้วต่ำที่สุด** · ไม่มี threshold ใหม่ (pool = K = 2N เดิม, ρ_adj = ฟังก์ชัน M010 เดิม) · 1 trial
3. ต่างจาก M010 (N=8, ข้ามเฉพาะ ρ_adj > 0.85, ยังเรียงตามอันดับ) และ M017 (คัดดัชนีก่อน) และ M008 (cap น้ำหนัก cluster): วิธีนี้ **เลือกความต่างเป็นเกณฑ์หลักภายในกลุ่ม momentum ดี** และใช้กับ N=3 ซึ่งการซ้ำทำให้พอร์ตเหลือเดิมพันเดียว (ที่ N=8 การซ้ำกินแค่ breadth)
4. หลักฐานวรรณกรรม **ปานกลาง–อ่อน**: การเลือกสินทรัพย์ momentum + ความต่าง (FAA: top 3 จาก 7 ด้วยอันดับ momentum + vol + correlation) และการคัดตามกลุ่ม (HRP/HCAA) ทำงานนอกตัวอย่างในระดับ **asset class** · ไม่มีงานระดับกองหุ้นกองทุนรวม · วิธีที่ใช้ Σ เต็ม (max-diversification) ไวต่อ Σ ผิดมากที่สุด (Jain & Jain 2019) → เลือกวิธีที่ใช้แค่ correlation รายคู่
5. คาดตรงๆ: เพิ่มจำนวนเดิมพันอิสระของ 3 กองแน่นอนเชิงกลไก แต่ **Sharpe ทิศไม่ชัด** (ต้องยอมเอากองอันดับ 4–6 แทนอันดับ 2–3 · ทีมเคยเห็น M010/M008 ที่กระจายออกจากธีมนำแล้ว Sharpe ลด) · ไม่ควรคาดว่าไปถึงระดับ N8 (0.97) · CI จะกว้างมาก (N3 base CI95% [−0.58, 1.92])

### อัลกอริทึม ณ วันตัดสินใจ t (สิ้นไตรมาส) — ขั้นที่ไม่ได้ระบุ = เหมือน M018-N3-GCGOLD ทุกบิต
```
ค่าคงที่: N = 3, K = 6, nmin = max(2, ⌈N/2⌉) = 2, cap = 0.40, MIN_W = 30 (ทั้งหมดลงทะเบียนแล้วใน M018/M010)

1. ctx_t, i_t, เกณฑ์คุณภาพ (AUM_fam ≥ 100 ล้าน, อายุ ≥ 730 วัน), reps = family_representatives(SR12′), ranks = rank_families(reps)
   — เหมือน run_m018.select ทุกบรรทัด (ข้อมูล ≤ t)
2. H = {} ถ้าไตรมาสก่อน fallback B0 ไม่งั้น H = holdings ไตรมาสก่อน (family -> FundCode)
3. (ถือต่อ) S = { fam: fc ∈ H | fam ∈ reps และ ranks[fam] ≤ K และ reps[fam].FundCode == fc }
   — ไม่ตัดกองถือต่อด้วย correlation (เหมือน M010 §3(ก)) · ถ้า |S| > N (เกิดไม่ได้ เพราะ H ≤ N) ไม่ต้องจัดการ
4. P = { fam ∈ reps | ranks[fam] ≤ K และ fam ∉ S }       # pool = family อันดับ 1..K ที่ยังไม่อยู่ใน S
5. (anchor) ถ้า S ว่าง และ P ไม่ว่าง: เพิ่ม fam ที่ ranks ต่ำสุด (อันดับ 1) จาก P เข้า S
6. (เติม) while |S| < N และ P ไม่ว่าง:
       สำหรับ c ∈ P:  score(c) = max_{s ∈ S} ρ̃(c, s)
                     ρ̃(c, s) = rho_adj_pair(wk[c], wk[s])  ;  ถ้า NaN (สัปดาห์ร่วม < 30 / ความแปรปรวนระยะยาว ≤ 0) → ρ̃ = 1.0
       เลือก c* = argmin score(c) · เสมอกัน (|Δ| < 1e-12) → ranks ต่ำกว่า (อันดับดีกว่า)
       S ← S ∪ {c*} ;  P ← P \ {c*}
7. ถ้า |S| < nmin (= 2) → fallback B0 (กติกา M018 เดิม) · ถ้า nmin ≤ |S| < N → ถือเท่าที่ได้ (ดู "ต้องให้ผู้ใช้ตัดสินใจ" ข้อ 4)
8. น้ำหนัก: ERC (LW lag-0 52 สัปดาห์, inverse-vol ถ้าสัปดาห์ร่วม < 30) → apply_cap(0.40) → คูณ x_t ของ GC75 · 1 − x_t = กองทอง (กติกา M018 §4.4 เดิม)
9. ซื้อขาย NAV วันทำการที่ 2 · ค่าธรรมเนียมจริง FeeData(legacy=False) · เหมือนเดิม
```
- ρ_adj = Γ0 + Γ1 + Γ1ᵀ (lag 1 สัปดาห์น้ำหนักเต็ม) หารด้วยความแปรปรวนระยะยาวของแต่ละกอง — **ฟังก์ชันเดิม `run_m010.rho_adj_pair` ห้ามแก้นิยาม** · ใช้ค่า**มีเครื่องหมาย** (ρ ติดลบ = ดีที่สุด)

## ความเสี่ยง / สิ่งที่คาดว่าจะเกิด
1. **เสีย momentum**: กองอันดับ 4–6 เข้าแทนอันดับ 2–3 · ถ้าธีมนำ (เช่น infra 2022, อินเดีย 2024) ยังวิ่งต่อ พอร์ตจะตามหลัง base — ทีมเห็นแล้วใน M008-GC (Δ −0.17) และ M010 (Δ −0.11) ที่ N = 8
2. **noise ของ ρ_adj 52 สัปดาห์**: Γ1 จาก 52 จุด noisy (DIAG ข้อจำกัด) → ลำดับ "ต่างที่สุด" อาจสลับไปมา · บรรเทาด้วยการไม่ตัดกองถือต่อ (turnover มาจากการเติมเท่านั้น)
3. **กองที่ correlation ต่ำมักเป็นกองแปลก** (ตลาดชายขอบ, ธีมแคบ, NAV ห่าง) → ความเสี่ยงเฉพาะสูง · เกณฑ์คุณภาพ AUM/อายุ ช่วยได้บางส่วน · ρ_adj NaN → ถือเป็น 1.0 จึงไม่เลือกกองข้อมูลน้อย
4. **ขากันทองต้องอ่านแยก**: ส่วนทองเหมือน base ทุกบิต → Δ ระหว่างวิธี 1 กับ base มาจากส่วนหุ้นเท่านั้น แต่ระดับ Sharpe ยังมีส่วน post-hoc ของทอง (M018 §7)
5. **path luck**: offset Sharpe ของ N3 0.02–1.02 · ขาลงจริงครั้งเดียว · ผลไตรมาสเดียวพลิกได้ → ตัดสินด้วย paired Δ + กลไก (DR², max ρ) ไม่ใช่ Sharpe เดี่ยว
6. ไม่มีอะไรในวรรณกรรมบอกว่าจะถึง Sharpe 0.95 หรือ 1.2 (เป้า M018) ด้วย 3 กอง

## คำแนะนำถึง quant-modeler
1. เขียน spec **M019 (1 trial, #45, DSR@45)** = วิธี 1 บน M018-N3-GCGOLD · ติดป้าย post-hoc บางส่วน (แรงจูงใจจากผล N3)
2. นำกลับมาใช้: `run_m018.select/stream` (แทนเฉพาะขั้นเติม), `run_m010.rho_adj_pair` + `RhoCache`, `wt.risk_parity_weights`, `wt.apply_cap(0.40)`, ขาทอง `select_gold`
3. เกณฑ์ผ่านที่ลงทะเบียนก่อนรัน (เสนอ): paired Δ Sharpe full vs N3-GCGOLD ≥ 0 **และ** DR² เฉลี่ยของส่วนหุ้นสูงกว่า base (กลไกทำงาน) · รายงาน N5/N8-GCGOLD เป็นบริบทเท่านั้น

## ต้องให้ผู้ใช้ตัดสินใจ
1. เลือก **วิธี 1 (corr ต่ำสุดใน top-6)** หรือ **วิธี 2 (แค่ตัดกองซ้ำ ρ_adj > 0.85)** — อย่างใดอย่างหนึ่ง ห้ามรันทั้งคู่แล้วเลือก
2. ยอมรับ pool = อันดับ ≤ 6 (= K เดิม) ไหม — ถ้าอยาก pool ใหญ่ขึ้นต้องเปลี่ยน K ด้วย (ต้นทุนซื้อแล้วขาย) และนับเป็นการเปลี่ยน 2 ส่วน
3. ERC ยังใช้ Σ lag-0 (ตามที่ผู้ใช้บอก "เหมือนเดิม") ขณะที่การคัดใช้ ρ_adj — ยอมรับความไม่สอดคล้องนี้ไหม (ข้อเสนอ: ยอมรับ เพื่อแยกผลของการคัดกอง)
4. กรณีได้ **2 กอง** (pool หมดหรือวิธี 2 ข้ามจนไม่ครบ): เพดาน 40% × 2 = 80% — `apply_cap` เดิมจะคืนน้ำหนักรวม 0.8 (อ่านจากโค้ด: ทุกตัวติดเพดาน ไม่มีที่กระจาย) · ส่วน 20% ที่เหลือให้ไป (ก) ขาทอง/กองตลาดเงินตามกติกา GC (ข) ปลดเพดานเป็น 50% เฉพาะกรณีนี้ (ค) ถือกองอันดับถัดไปแม้ซ้ำ — วิธี 1 แทบไม่เจอกรณีนี้ (pool 6 มักพอ) แต่ต้องล็อกก่อนรัน
5. รันเฉพาะขา **GCGOLD** (1 trial) ตามที่ผู้ใช้ระบุ — ไม่รัน GCMMF/EQ100 คู่ (แต่ละแบบ = trial)
6. ยอมรับป้าย post-hoc บางส่วน และเกณฑ์ผ่าน "Δ ≥ 0 + DR² สูงขึ้น" ไหม

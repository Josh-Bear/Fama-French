## บทสรุป 5 บรรทัด
1. `Actual Value` = อัตราที่**เรียกเก็บจริง** (fact sheet ของไทยแสดงทั้ง "เพดาน" และ "เก็บจริง") → backtest ใช้ถูกคอลัมน์แล้ว · ส่วนการยกเว้น front-end ที่เห็นในแหล่งเป็น**โปรโมชันชั่วคราวที่ผูกกับช่องทาง**เป็นหลัก ไม่ใช่ค่าที่ได้ประจำ
2. แพลตฟอร์มตัวกลาง (FINNOMENA) บอกเองว่าค่าธรรมเนียม**เท่ากับซื้อตรงกับ บลจ./ธนาคาร** (ไม่มีส่วนลด) → กรณี (ก) "จ่ายเต็ม" ใกล้ความจริงที่สุด · กรณี (ข) "ยกเว้น front-end ทั้งหมด" **หลวมเกิน** ถ้าใช้เป็นตัวเลขหลัก
3. กองตลาดเงินส่วนใหญ่ไม่เก็บค่าซื้อ/ขาย และได้เงิน T+1 → ขาเงินสดไม่มีต้นทุน = **สมจริง** · กำไรจากการขายหน่วยของบุคคลธรรมดาได้รับยกเว้นภาษี → ไม่คิดภาษี = **สมจริง** (สำหรับนักลงทุนบุคคล)
4. ช่องโหว่ใหญ่ที่สุดไม่ใช่อัตราค่าธรรมเนียม แต่เป็น**เวลา**: กอง FIF ได้เงินขายคืน T+1 ถึง T+6 · สับเปลี่ยน FIF → กองตลาดเงินได้ราคาขาเข้าที่ T+2–3 · สับเปลี่ยนข้ามประเทศโดยทั่วไป T+5 (นานถึง ~10 วันถ้าติดวันหยุด) → backtest ที่ซื้อขายเสร็จในวันเดียว**หลวมเกิน**
5. ยังไม่พบหลักฐานที่เปิดอ่านได้เรื่องค่าปรับขายก่อนกำหนดของกอง FIF ไทย และขั้นต่ำการซื้อ → ให้ validator ตรวจรหัสอื่นใน SecFundFee (CF/TF/OT ที่ spec ตัดทิ้ง) ก่อนสรุปว่าไม่มี

## รายละเอียดต่อคำถาม

### 1) `Actual Value` คือค่าเก็บจริงหรือเพดาน · ส่วนลด/ยกเว้นมีบ่อยแค่ไหน
- ก.ล.ต. อธิบายว่าส่วนค่าธรรมเนียมของ fund fact sheet แสดงทั้งเพดานสูงสุดและค่าที่เก็บจริง [S1] และหนังสือชี้ชวนส่วนสรุปของ บลจ. ใช้รูปแบบ "สูงสุดไม่เกิน x% / เก็บจริง y%" [S2] → ใน SecFundFee คู่ `Rate` / `Actual Value` สอดคล้องกับ 2 ช่องนี้ (การจับคู่ชื่อคอลัมน์ ↔ ช่องในเอกสาร อิงจาก schema PDF ที่ spec อ้าง — **ไม่ได้ตรวจซ้ำเอง**)
- ก.ล.ต. ยังระบุว่า บลจ. อาจเก็บค่าธรรมเนียมขายต่างกันตามกลุ่มผู้ลงทุน เช่น ยกเว้นให้สถาบัน [S1] → `Actual Value` คือค่าของผู้ลงทุนรายย่อยทั่วไป ไม่ใช่ราคาที่ทุกคนจ่าย
- ส่วนลดผ่านแพลตฟอร์ม: FINNOMENA ระบุว่าค่าธรรมเนียมเท่ากับซื้อผ่าน บลจ./ธนาคาร และไม่เก็บเพิ่ม [S3][S4] (รายได้มาจาก retrocession ของ บลจ.) → **ไม่มีหลักฐานว่าแพลตฟอร์มให้ส่วนลด front-end ถาวร**
- ยกเว้นโดย บลจ.: ตัวอย่างที่เปิดอ่านได้ SCBAM ยกเว้น front-end + switching-in ของ SCBCHEQA และ SCBDIGI เฉพาะผ่านแอป SCBAM Fund Click, 2–27 ก.พ. 2569, เฉพาะผู้ที่เปิดบัญชีเองโดยไม่ผ่านผู้แนะนำ [S5] → ลักษณะเป็นโปรชั่วคราว
- ความถี่ของการยกเว้น: **ไม่พบแหล่งที่วัดความถี่** — ต้องให้ผู้ใช้ยืนยันกับช่องทางที่จะใช้จริง

### 2) การสับเปลี่ยน
- ภายใน บลจ. เดียวกัน: ทำได้ทั่วไป (KAsset/Eastspring มีตารางสับเปลี่ยนภายใน บลจ. [S11][S7])
- ข้าม บลจ.: ตัวกลางใน FundConnext เปิดให้ "สับเปลี่ยน" ข้าม บลจ. ได้แต่มีขั้นตอนเพิ่ม [S8] · การโอนย้ายข้าม บลจ. ที่ treasurist อธิบายไว้เน้นกองลดหย่อนภาษี (RMF/SSF) ซึ่งเป็นกติกาเฉพาะ [S16 — เปิดได้แต่เนื้อหาไม่ครบ] → สำหรับกองทั่วไป ข้าม บลจ. ในทางเศรษฐศาสตร์ = ขาย (BF) + ซื้อ (FF) + รอเงิน → สูตรใน spec ถูกด้านอัตรา แต่ขาดด้านเวลา (A7)
- SI = FF หรือไม่: แหล่งที่เปิดได้ไม่ยืนยัน · snippet ระบุว่า SI มักไม่เก็บเพราะเก็บใน FF แล้ว (**ยังไม่ยืนยันแหล่ง**) · ข้อมูลจริงของเรามี SI แยกต่อกองอยู่แล้ว จึงไม่ต้องสมมติ
- คิดทั้งสองขา: เอกสารไทยแยก "สับเปลี่ยนเข้า" และ "สับเปลี่ยนออก" เป็นคนละรายการ [S2 รูปแบบ; S15] → การคิด SO + SI ตามอัตราของแต่ละกองสอดคล้อง

### 3) เงินสด / กองตลาดเงิน
- กองตลาดเงินส่วนใหญ่ไม่เก็บค่าซื้อขาย เหมาะใช้เป็นกองพัก และได้เงิน T+1 [S9]
- สับเปลี่ยนหุ้น FIF → ตลาดเงิน ใน บลจ. เดียวกัน: ค่าธรรมเนียมฝั่งตลาดเงินเป็น 0 ได้ แต่ฝั่ง FIF ยังโดน SO/BF ตามกอง (backtest คิดไว้แล้วผ่านขากอง) · ราคาขาเข้ากองตลาดเงินได้ที่ T+2–3 [S11] → 2–3 วันที่ไม่ได้ทั้งหุ้นและดอกเบี้ย (เล็ก)
- ข้อสังเกตเชิงโครงสร้าง: backtest ให้เงินสดได้ rf 2% โดยไม่ระบุว่าเป็นกองตลาดเงินของ บลจ. ไหน — ถ้าพอร์ตมีกองจากหลาย บลจ. การย้ายเข้าเงินสดจะสับเปลี่ยนได้เฉพาะส่วนของ บลจ. ที่มีกองตลาดเงิน (เกือบทุก บลจ. ใหญ่มี — **ยังไม่ยืนยันแหล่ง**)

### 4) Settlement / timing
- Eastspring: เงินขายคืน FIF T+1 ถึง T+6 · หุ้นไทย T+2 · ตลาดเงิน T+1 [S10]
- Eastspring ตารางสับเปลี่ยน: FIF → ตลาดเงิน ขาเข้า T+2–3 · ตลาดเงิน → FIF ขาเข้า T ถึง T+4 · สับเปลี่ยนโดยรวม 2–4 วันทำการ [S11]
- FINNOMENA: สับเปลี่ยนกองต่างประเทศ ~T+5 (สูงสุด ~10 วันถ้าติดวันหยุด) เรียกช่วงนี้ว่า "ช่วงสูญญากาศ" และแนะนำใช้กองตลาดเงินเป็นตัวกลางเพื่อซื้อกองปลายทางได้ทันที [S12]
- ผลต่อ backtest: (i) ส่วนที่หมุนออกจากตลาด 2–6 วันทำการต่อ rebalance · (ii) ราคาซื้อกองปลายทางไม่ใช่ NAV วัน rebalance แต่เป็น NAV วัน T+k · (iii) ถ้าใช้วิธี "ซื้อก่อนด้วยกองตลาดเงิน" ตาม [S12] จะลบ (i)/(ii) ได้แต่ต้องมีเงินสดกันไว้ ซึ่งพอร์ตของเรามีขาเงินสดอยู่แล้วในบางโมเดล
- ทิศของ bias: ค่าคาดหวังน่าจะเล็ก (ไม่กี่วันของ equity premium) แต่เป็น noise ที่ backtest ไม่มี · **แหล่งไม่ให้ตัวเลข %/ปี** — ต้องจำลองโดยเลื่อนวันซื้อเป็น T+k

### 5) ค่าใช้จ่ายอื่น
- ภาษี: บุคคลธรรมดาได้รับยกเว้นภาษีกำไรจากการขายหน่วย (KAsset [S13], Dime [S14]) · นิติบุคคลต้องเสียภาษี [S13] · ปันผล 10% หัก ณ ที่จ่าย [S14] · มาตรา/กฎกระทรวงที่เป็นฐาน — **ยังไม่ยืนยันแหล่ง** (snippet หนึ่งอ้างว่า มาตรา 42(23) ถูกยกเลิก — ไม่ได้เปิดอ่าน จึงไม่ใช้)
- ค่าโอนหน่วย: บาทต่อรายการ (snippet: 50 บาท/รายการ) — **ยังไม่ยืนยันแหล่ง** · ไม่เกี่ยวกับการซื้อ/ขาย/สับเปลี่ยน
- ค่าปรับขายก่อนกำหนด: มีเป็นหมวดค่าธรรมเนียมในไทย [S15] แต่ไม่พบตัวอย่าง FIF ที่เปิดอ่านได้ — spec ตัด `CF/TF/OT` ทิ้ง ซึ่งอาจซ่อนรายการนี้ไว้
- ขั้นต่ำการซื้อ: ไม่พบแหล่งที่เปิดได้ — **ยังไม่ยืนยันแหล่ง**

## คำแนะนำถึง backtest-validator / quant-modeler (หลัง audit ปัจจุบันเสร็จ · 0 trial — เป็นการเปลี่ยนวิธีวัด)
1. **ใช้กรณี (ก) จ่ายเต็มเป็นตัวเลขหลัก** · รายงาน (ข) เป็น upper bound พร้อมป้าย "ต้องมีโปรยกเว้นทุกครั้ง ซึ่งแหล่งไม่สนับสนุน"
2. **sensitivity เรื่องเวลา**: เลื่อนวันซื้อกองปลายทางเป็น T+3 และ T+5 วันทำการ (ช่วงอิง [S10][S11][S12]) โดยส่วนที่ค้างอยู่ได้ผลตอบแทน 0 (หรือ rf ถ้าผ่านกองตลาดเงิน) · ข้าม บลจ. ใช้ T+5, ภายใน บลจ. ใช้ T+3
3. ตรวจรหัส `CF/TF/OT` ใน SecFundFee ว่ามี exit fee/ค่าปรับถือสั้นของกองที่เคยถือไหม (เน้น M006/M007 ที่ปรับเงินสดรายเดือน)
4. ไม่ต้องเพิ่มภาษีหรือค่าโอนหน่วย (สมมติลูกค้าเป็นบุคคลธรรมดา — ต้องให้ผู้ใช้ยืนยัน)

## ต้องให้ผู้ใช้ตัดสินใจ
- ลูกค้าเป้าหมายเป็น **บุคคลธรรมดา หรือ นิติบุคคล** (นิติบุคคลต้องเพิ่มภาษีกำไร → สมมติฐานปัจจุบันหลวมเกิน)
- จะซื้อผ่าน **ช่องทางไหน** (แอป บลจ. / ธนาคาร / ตัวกลาง FundConnext) — มีผลว่าจะได้โปรยกเว้น front-end บ้างหรือไม่ และสับเปลี่ยนข้าม บลจ. ได้แบบไหน
- ยอมให้ validator เพิ่ม sensitivity เรื่อง T+k (เปลี่ยนวิธีวัด ไม่นับ trial) หรือไม่

### M023-TR3 — แบ่งทุน 3 ก้อน rebalance รายไตรมาสคนละเดือน (base M019) · ง่าย · **รันก่อนทุกตัว**
1. สร้าง env/plan offset k = 0,1,2 ตาม `run_m019.main` §[3/4] (`fu.build_env_and_plans(k)`, `m18.gold_sels(GD, Ek)`, `stream_lc(Ek["ctx_h"], Ek["quals"], 9, False)`, `gc_gold_plan`) → `plan_k`
2. t0 = `plan_0[0]["t"]` (2022-03-31) · `plan_j = [plan_0[0]] + [p for p in plan_k=j if p["t"] > t0]` สำหรับ j = 1,2 · `plan_0` เดิม
   (state กฎถือต่อของแต่ละก้อน = ของ stream offset j เอง — ไม่ต้องแก้ stream)
3. `V_j = sim(plan_j, ["full","nofront","c0"], E)` ด้วย **ปฏิทินเดือนของ offset 0 (`E["months"]`)** ทุกก้อน · ต้นทุนคิดแยกก้อน (ไม่ netting ข้ามก้อน = อนุรักษ์นิยม)
4. `V = (V_0 + V_1 + V_2)/3` (ทุกก้อนเริ่มที่ค่าเดียวกัน ณ e แรก) → `rr.metrics(V, real)` = **ข้อ 1 ของ TR3** (Sharpe > 1.2 และ CAGR > 12%)
5. ไม่มีการ rebalance ระหว่างก้อน (ปล่อย drift) · พารามิเตอร์: 3 ก้อน (= ความยาวไตรมาส) ไม่มีค่าให้จูน
6. **ข้อ 2 ของ TR3 (นิยามของ spec นี้)**:
   - (a) **start-shift** (ตามที่ผู้ใช้ระบุ): variant s ∈ {0,1,2} = ทั้ง 3 ก้อนเริ่มด้วย `plan_s[0]` ณ วันตัดสินใจแรกของ offset s แล้วก้อน j เดิน stream (s + j) mod 3 ต่อ ·
     วัดบน **ช่วงร่วม ก.ค. 2022–ธ.ค. 2025** (เทียบได้กับ offset test เดิม) → **เกณฑ์: เฉลี่ย 3 ค่า ≥ 1.0** · หมายเหตุ: โดยกลไกจะใกล้กันมาก
   - (b) **ตัวตรวจที่ไม่ผ่านโดยกลไก (ต้องรายงาน · ใช้ตัดสินร่วม)**: ทิ้งทีละก้อน — `(V_a + V_b)/2` สำหรับ {0,1},{0,2},{1,2} บนช่วงร่วม → **ค่าต่ำสุด ≥ 0.9**
     (ถ้าพอร์ตพึ่งก้อนที่ฟลุ๊คก้อนเดียว ค่านี้จะตก) · และ Sharpe แบ่งครึ่งช่วง (ก.ค. 2022–ธ.ค. 2023 / ม.ค. 2024–ธ.ค. 2025) รายงานคู่ (ไม่ตัดสิน)
7. diagnostic (0 trial): Δ ผลตอบแทนรายไตรมาส offset 0 − offset 1 ของ M019 (จาก `V` ของ sim offset ที่มีแล้ว) + ไตรมาสที่ช่องว่าง > 3 pt พร้อม x_t (สัดส่วนหุ้น) ของทั้งสอง offset
- **regression**: (i) `plan_0` ซ้ำ 3 ก้อน → V = M019 ทุกบิต · Sharpe full = **1.098098** (|Δ| < 5e-7) · (ii) Sharpe ช่วงร่วมของ `plan_k` เดี่ยว (sim ด้วย `Ek`) = `M019_offsets.csv` (0.5831 / 0.9500)
- รายงานเพิ่ม: จำนวนกองหุ้น distinct ที่ถือพร้อมกันสูงสุด/เฉลี่ย · จำนวนรายการซื้อขายต่อปี (ภาระปฏิบัติ)

### M024-FEE0 — ตัวเติมและ class ที่ค่าธรรมเนียมขาเข้าต่ำเมื่อเกือบเสมอ (base M019) · ง่าย
แก้เฉพาะ `select_lc` (ข้อมูล ≤ t):
1. `ff(c) = fee.rate(c, "FF", t)` (Fee3 · แถว As of ≤ **t** · ค่าที่อ่านไม่ได้ → median ตามกติกา fees.py เดิม) · ทำ `fee` ให้ `select_lc` เรียกได้
2. **class**: หลัง `reps = family_representatives(...)` สำหรับ family ที่ **ไม่ได้ถืออยู่**: `B = {class c ใน family ใน I_t ที่ผ่านคุณภาพ : SR12′(c) ≥ SR12′(rep) − 0.05}` → ใช้ class ที่ `ff` ต่ำสุดใน B
   (เสมอ → SR12′ สูงกว่า → FundCode) **แทน FundCode เท่านั้น** · `signal`/`vol52` ของ family = ค่าเดิม → `rank_families` ไม่เปลี่ยน
3. **ตัวเติม**: `s* = min score` · `C = {c ∈ P∖S : score(c) ≤ s* + 0.10}` · เลือก `ff` ต่ำสุดใน C · เสมอ → score ต่ำกว่า → อันดับดีกว่า
4. ส่วนอื่น (anchor อันดับ 1, กฎถือต่อ, ERC, GC, ทอง) เหมือน M019
- พารามิเตอร์ค่าเดียว: ε = 0.05 (≈ ผลของค่าจัดการต่างกัน ~0.75%/ปี ที่ vol 15% — แคบพอไม่สลับ hedge class ที่ต่างชัด) · δ = 0.10 (ของ researcher: < 1 se ของ ρ 52 สัปดาห์)
- **regression**: ε = 0 และ δ = 0 → น้ำหนัก = `M019_weights.csv` ทุกบิต (max|Δw| < 1e-12) · Sharpe 1.098098
- รายงานเพิ่ม: จำนวนครั้งที่ class/ตัวเติมเปลี่ยนจาก M019 · FF เฉลี่ยของกองที่ซื้อ เทียบ M019 · จำนวนครั้งที่ใช้ snapshot ค่าธรรมเนียมเก่าสุด (ก่อน snapshot แรก)

### M025-HOLD18 — แถบถือต่อ rank ≤ 18 (base M019) · ง่าย
แก้บรรทัดเดียวใน `select_lc`: `S = {fam: fc ∈ H_map : ranks[fam] ≤ 18 และ reps[fam]["FundCode"] == fc}` (เดิม `fam in pool` = rank ≤ 9) · กลุ่มผู้สมัครสำหรับ **เติม** ยังเป็น rank ≤ 9 · ถ้าถือต่อครบ 3 → ไม่เติม
- พารามิเตอร์ค่าเดียว: 18 = 2 × pool (ธรรมเนียม K = 2N ของทีม)
- **regression**: แถบ = 9 → M019 ทุกบิต · Sharpe 1.098098
- รายงานเพิ่ม: turnover/cost เทียบ M019 · จำนวนไตรมาส × กองที่ถือต่อเพราะแถบใหม่ (อันดับ 10–18) และผลตอบแทนไตรมาสถัดไปของกองเหล่านั้น

### M026-DEFX — ขาที่ไม่ใช่หุ้น = กอง O/F ที่ excess return 12 เดือนสูงสุด (base M019) · ง่าย
แทน `GS = m18.gold_sels(GD, E)` ด้วย `DS` (โครง `(v, info, table)` เดิม → `gc_gold_plan` ไม่ต้องแก้):
1. ข้อมูล: GData แบบไม่กรองชื่อ GOLD = กอง policy O **ทั้งหมด** (cache parquet **ไฟล์ใหม่** ห้ามทับ `m018_navO_gold.parquet`) + กอง F ทั้งหมดใน `FD` · snapshot/คุณภาพเหมือน GData/FData (retail, ไม่ใช่ class ภาษี, it_at, Quality pass_q1&q2)
   · Fee3 ต้องครอบกอง O ใหม่ทั้งหมด
2. ณ t: `D_t = I_t^O ∪ I_t^F` ที่ผ่านคุณภาพ · ตัดกองที่ `ρ_adj(f, ACWI)` 52 สัปดาห์ ≤ t > 0.5 (`r10.rho_adj_pair` · ACWI รายสัปดาห์ชุดเดียวกับ GC75 · สัปดาห์ร่วม < 30 → ตัดทิ้ง)
3. class ตัวแทนต่อ family = SR12′ สูงสุด (กติกาเดิม) · **เลือก 1 family ที่ `R12_1 − h_t` สูงสุด** (ไม่ใช่ SR12′ — เหตุผล §1 ไอเดีย 5) · เสมอ → AUM_fam ใหญ่กว่า
4. ถ้าค่าสูงสุด ≤ 0 หรือ D_t ว่าง → `{}` → เติมด้วยกองตลาดเงิน FAUM (เส้นทาง `make_plan_F` เดิม)
- พารามิเตอร์ค่าเดียว: ρ ≤ 0.5 (ของ researcher) · 1 กอง
- **regression**: จำกัด D_t = กองทอง (GData เดิม) + ตัด ρ filter + เกณฑ์ "AUM_fam สูงสุด" → `DS` = `GS` ทุกไตรมาส → M019 ทุกบิต · Sharpe 1.098098
- รายงานเพิ่ม: กองที่เลือกรายไตรมาส + policy + ρ_adj กับ ACWI + R12_1 − h · จำนวนไตรมาสที่ได้ทอง / อื่น / ตลาดเงิน · ผลตอบแทนขากันรายปีเทียบทอง

### M027-MH — คะแนนกอง 3 horizon แบบ annualize (base M019) · **ปานกลาง**
ณ t ทุกกองใน `ctx["i_t"]`: `ms = fs.month_end_points(calendar, t, 13)` (ms[-1] = สิ้นเดือนของ t)
```
R_L(f) = NAV(ms[-1]) / NAV(ms[-1-L]) − 1   (fs._asof tol 10 วัน · NAV ≤ t)        L ∈ {3, 6}
h_L    = r11.hurdle(rate, ms[-1-L], ms[-1])
SR_L   = (R_L − h_L) · (12/L) / vol52(f)                                   # annualize ให้หน่วยเท่ากัน
SR_12  = SR12′ เดิม (R12_1, h_t, vol52)                                     # คงนิยามเดิม
MH(f)  = เฉลี่ยของ {SR_3, SR_6, SR_12} ที่ไม่เป็น NaN (SR_12 ต้องมีเสมอ — i_t ตัด NaN อยู่แล้ว)
```
แทนคอลัมน์ `i_t["SR12"]` ด้วย MH ในสำเนา `ctx_h` (ทั้ง 3 offset) ก่อน `stream_lc` → การเลือก class ตัวแทน / อันดับ / กฎถือต่อ / เติม ใช้ MH อัตโนมัติ · GC, ทอง, ERC ไม่เปลี่ยน
- พารามิเตอร์: {3, 6, 12} น้ำหนักเท่ากัน (ชุดเดียวกับสัญญาณ GC75) · ไม่มีค่าใหม่
- **regression**: น้ำหนัก (0, 0, 1) → `i_t["SR12"]` เดิมทุกบิต → M019 · Sharpe 1.098098 · และ assert ว่า R_L ใช้ NAV วันที่ ≤ t เท่านั้น
- รายงานเพิ่ม: Spearman(MH, SR12′) รายไตรมาส · จำนวนกองที่ต่างจาก M019 · turnover/cost

### M028-STACK — TR3 × (M019 + ส่วนประกอบที่ผ่าน) · ง่ายเมื่อ M023–M027 เสร็จ · **รันท้ายสุด**
- **กติกาคัดส่วนประกอบ (ลงทะเบียนล่วงหน้า · เปิด/ปิด ไม่จูนค่า)**: รวม X ∈ {FEE0, HOLD18, DEFX, MH} ถ้า Sharpe 45 เดือนของ **X-TR3 ≥ M023-TR3** · ไม่มีตัวผ่าน → ไม่รัน (ไม่เสีย trial)

## 5. คาดว่าแบบไหนมีโอกาสถึงเป้าที่สุด
- **M028-STACK** — เป็นแบบเดียวที่รวมคันโยก 2 ด้าน: TR3 (ทำให้ข้อ 2 แข็งโดยกลไก) + การลดต้นทุน (FEE0 + HOLD18 — เพดานรวม ~+0.12 จาก front-end, คาดได้ +0.04–0.08) + อาจได้สัญญาณ/ขากันที่ดีขึ้น ·
  ประมาณ TR3 ~1.0 + 0.05–0.10 → **ยังมีโอกาสต่ำกว่า 1.2** (ผมให้ ~20%) · CAGR > 12% น่าจะผ่าน (M019 nofront 16.2%, offset เฉลี่ยราว 13%)
- ในตัวเดี่ยว **M027-MH** คือแบบที่ "อาจกระโดด" มากที่สุด (เปลี่ยน return ไม่ใช่แค่ต้นทุน) แต่ก็อาจแย่ที่สุด · M024/M025 ปลอดภัยแต่ได้น้อย · M026 ขึ้นกับปี 2022 ล้วน
- ถ้ารอบนี้ M028-TR3 ไม่ถึง ~1.1 ผมจะเสนอรอบ 2 ว่าโจทย์ "Sharpe > 1.2 หลังค่าธรรมเนียมขาเข้าเต็ม" ต้องการคันโยกด้าน return ใหม่ (ไม่ใช่แค่ลดโชค) และจะถามผู้ใช้ตรงๆ
  ว่าการสมมติจ่าย front-end เต็มทุกครั้งตรงกับการลงทุนจริงไหม (R005: มักถูกยกเว้น) — **ไม่ใช่เพื่อเปลี่ยนนิยามให้ผ่าน** แต่เพราะมันคือ 100% ของต้นทุนในโมเดล

```
  pctrank_m คิดบน reps ของ t เท่านั้น · f ไม่มีค่าที่ m → ใช้ pctrank_t ของ f แทน (แบบ `pr.where(pr.notna(), sr)` เดิม) · ก่อน 2022-03 ไม่มี ctx → ใช้เดือนที่มี
ranks = wt.rank_families(score = s_f) แล้วทุกอย่างต่อ (pool ≤ 9, S_keep, ρ_adj filler, ERC, cap) เหมือนเดิม — ช่องทางเดียวกับ cfg.sigs
```
- พารามิเตอร์ 3 = จำนวนเดือนในไตรมาส = จำนวน offset (โครงสร้าง) · หลักการ "เฉลี่ยสัญญาณข้ามวันตัดสินใจ" = tranche ของสัญญาณ (Hoffstein) · ลด turnover = ลดต้นทุนที่ offset 1
- คาด: offsets เข้าใกล้กัน (ส่วนที่ต่างกันคือ noise ตาม §0.1) → off1 ขึ้น, **off0 มีแนวโน้มลด** (การคัดของ offset 0 อาจโชคดี) · ข้อ 2 headroom M046 แค่ +0.044 → **เสี่ยงหลุดข้อ 2 สูง**
- ทำไมยังเสนอ: เป็นไอเดียเดียวที่แก้ต้นเหตุหลัก (การคัดกอง) แทนการอุดอาการ · แต่บทเรียน R1/R2: ทุกอย่างที่แตะการคัดกอง = เปลี่ยนเส้นทางทั้งชุด ผล ±0.1–0.2 แบบสุ่ม
- ยาก: ปานกลาง (โหลด ctx_h ของ 3 offset รวมเป็นแผนที่เดือน → SR12′) · regression: ชุดเดือน = {t} → M042/M046 ทุกบิต

## 4. คำแนะนำถึง modeler
1. **D0 ก่อน** (เสนอผู้ใช้ · 0 trial) แล้วคำนวณ M042/M046 ใหม่ทุก offset — ถ้า M046+D0 off1 ≥ 0.9 แล้ว ให้รายงานผู้ใช้ก่อนเพิ่ม trial

## 5. ต้องให้ผู้ใช้ตัดสินใจ
1. **อนุมัติ D0 (ซ่อม NAV K-GOLD-C(A))** หรือ R5-4 (เปลี่ยน class ทองเป็น AUM ใหญ่สุด) หรือไม่ทำทั้งคู่ — ตัวเลข offset 1/2 ของทุกรอบที่ผ่านมามีความผิดนี้ปนอยู่

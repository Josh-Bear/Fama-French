## ข้อที่ตรวจแล้วไม่เป็นปัญหา

- **Look-ahead ของสัญญาณ/Σ/SMA200**: `fund_signals.py` ใช้ `calendar[calendar <= t]` และ `_asof` (searchsorted แบบ ≤ day) สม่ำเสมอทุกจุด (weekly/month-end anchors, R12_1, vol52, SR12); `weighting.vol_target_cash`/`trend_filter_cash` ก็ slice ด้วย `.tail()`/`.loc[:t]` เช่นกัน — ไม่พบ index ที่หลุดเกิน t แม้ไม่มี `assert` ชัดแจ้งตามที่ spec ขอ (เป็นจุดอ่อนเชิง defensive-coding เล็กน้อย ไม่ใช่บั๊กจริง)
- **Family map / H-UH grouping / tax-class exclusion**: สร้างจากรหัสกองล้วน (regex บน FundCode) ไม่แตะผลตอบแทน ตรงตาม C2 — ตรวจโค้ด `fund_signals.family_of/is_tax_class/is_dividend` แล้ว
- **Cash leg (C7)**: ตรวจ `simulate.py` บรรทัด 93-131 — ขา `__CASH__` ไม่เสียต้นทุน ไม่นับ turnover ตามที่สเปกต้องการ, โตด้วย rf ผ่าน `_grow_cash`, money-conservation assert ผ่าน; ต้นทุน 0.5%/ข้าง คำนวณถูก (cost_side × Σ|Δw| ต่อกอง ครอบทั้งขาย/ซื้อ)
- **MAX(VT,TF) overlay ของ M005**: `run_m002_m005.py:163` `c = min(0.25, max(c_vt, c_tf))` ตรงตามสเปก (ทั้งสองค่าถูก clip ที่ 0.25 อยู่แล้วในแต่ละฟังก์ชัน) — ไม่ใช่บั๊ก ที่ M005 แพ้ TF/NODD มาจาก VT ลากลง (ดูข้อ 2) ไม่ใช่ implementation ผิด
- **trials.csv**: เทียบกับ `trials.backup_20260930T231832.csv` เชิงโปรแกรม (field ตัวเลขทุกตัว: sharpe/cagr/vol/max_dd/turnover/n_trials_cumulative/deflated_sharpe/period) — **ไม่มี mismatch แม้แถวเดียว** ยืนยันคำกล่าวอ้างของ validator ว่าไม่ได้แก้ตัวเลขเดิม (เปลี่ยนแค่คอมมาเป็น `;` ใน notes) · `n_trials_cumulative` ไล่ 1→13 ถูกต้องตามลำดับการรัน
- **Apply_cap (C6)**: ตรวจ logic redistribution กรณี N=4 เพดานพอดี 25%×4=100% — converge ถูกต้อง ไม่มี edge case เงินหาย

## คำตัดสิน: **ผ่านแบบมีเงื่อนไข** (conditional pass)

การทดลองสะอาดกว่า M001 มาก (ไม่มี look-ahead ที่ตรวจพบ, trials.csv ถูกต้อง, cash leg/cost ถูกต้อง) แต่**ยังนำเสนอ M005 พร้อม DSR ปัจจุบันไม่ได้** เพราะ DSR เฟ้อ (บั๊ก unit annualized/per-period) — ต้องแก้ข้อ 1 ก่อน (งานเล็ก, <1 ชม.) แล้ว regenerate ตาราง DSR ทั้งหมดใหม่ก่อนเสนอพี่เลี้ยง

## 3 ปัญหาร้ายแรงที่สุด (สำหรับสรุปให้ผู้ใช้)

1. DSR ในไฟล์ผลลัพธ์ปัจจุบันเฟ้อเกินจริง (bug unit) — ตัวเลขจริงหลังแก้: ไม่มี trial ไหนถึง DSR 50% (สูงสุดคือ M005-N5 = 0.447) → **หลัง 13 trials ยังไม่มีอะไรพิสูจน์ทางสถิติได้ว่าดีกว่าสุ่ม**
2. M005 (ตัวเสนอ) แพ้ parent ทั้ง TF และ NODD ใน point estimate, ร่วงหนักสุดเมื่อตัดไตรมาสที่ดีที่สุดออก (0.455→0.139) — สะท้อนว่า vol-target overlay (องค์ประกอบเดียวที่พิสูจน์ได้ว่าลบ, CI ไม่คร่อม 0) เป็นตัวฉุด
3. เป้า Sharpe ≥ 0.95 ยังไม่ถึงในทุก 11 trials (จุดสูงสุด M005-N5 = 0.845) และแม้ M005-N5 เอง DSR ก็แค่ 0.447 — บ่งชี้ว่าเป้า 0.95 อาจ**ไม่สมจริง**สำหรับ universe/ช่วงเวลานี้ตามที่ BRIEF เตือนไว้แต่แรก (realistic range 0.4-0.7)

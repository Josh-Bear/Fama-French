## 1. สมมติฐาน (ex-ante)
1. **เกณฑ์สัมบูรณ์ (absolute momentum) ขาเข้า**: อันดับ cross-sectional อย่างเดียวบังคับซื้อ "กองที่แย่น้อยที่สุด" ในตลาดขาลง (ตัวอย่างปี 2022:
   ทั้ง universe แทบไม่มีกองที่ชนะ rf) · dual momentum (Antonacci 2014) / TSMOM รายสินทรัพย์ (Moskowitz–Ooi–Pedersen 2012) เสนอให้ถือเฉพาะสินทรัพย์ที่ผลตอบแทนเกิน rf
   → M014 ใช้รูปแบบ "เข้มกว่า" คือเกิน rf ≥ 1 เท่าของ vol (≈ Sharpe 11 เดือน ≥ 1) · R002: momentum crash เกิดตอนตลาดกลับตัว → เกณฑ์สัมบูรณ์ลดการไล่ซื้อกองที่ momentum อ่อน
   (ไม่ได้เปิดอ่านต้นฉบับซ้ำเอง)
2. **กองถือต่อไม่ถูกตัด** (ผู้ใช้กำหนด): คง hysteresis เดิม → ลด turnover/ค่าธรรมเนียม · ผลคือเงินสดจากเกณฑ์จะเกิดเฉพาะเมื่อกองถือหลุดอันดับ 16 แล้วไม่มีผู้ผ่าน 1.0 มาแทน
3. ต่างจาก M006-TCA (ตัดน้ำหนักกองที่ R12 < 2%): M014 กรองเฉพาะขาเข้าและเกณฑ์สูงกว่ามาก
4. คาด: 2022 Q3–2023 Q1 ไม่มีกองใหม่ (§5) → เงินสดค่อยๆ สะสมตามกองที่หลุดอันดับ · ช่วงขาขึ้นกองผ่าน 7–84 family → ส่วนใหญ่เต็ม 8 · Δ ไม่แน่ทิศ, path luck ปานกลาง
   (selection เปลี่ยนเฉพาะไตรมาสที่มีขาเข้า SR ≤ 1)

## 2. อัลกอริทึม ณ t
### 2.1 การคัด
```
reps, ranks = เหมือน M012-QF-S (mode "S") — family_representatives(I_t′, "SR12", held_funds) → rank_families(reps)
H_map = held (ไม่มี prev_fb แล้ว เพราะไม่มี fallback)

(keep)  สำหรับ fam, fc ใน H_map:  ถ้า fam ∈ reps และ ranks[fam] ≤ 16 และ reps[fam].FundCode == fc → S[fam] = fc        # = hysteresis เดิม ไม่ดูเกณฑ์ 1.0
(fill)  สำหรับ fam เรียงตาม ranks:  ถ้า |S| ≥ 8 หยุด · ข้ามถ้า fam ∈ S · ข้ามถ้า not (reps[fam].signal > SR_MIN) · ไม่งั้น S[fam] = reps[fam].FundCode
        SR_MIN = 1.0 (เข้มงวด >) · signal NaN = ไม่ผ่าน
ไม่มีขั้น fallback · held ไตรมาสถัดไป = S (แม้ว่าง)
```
- implement: ฟังก์ชันใหม่ `select_sr(reps, ranks, held_map, sr_min, use_fallback)` (โครงเดียวกับ `run_m012.select_K`) · assert: `sr_min = −∞, use_fallback = True` →
  ผลเท่า `wt.hysteresis_select(..., 8, 16, None)` ทุกไตรมาส (S และ flag fallback)

### 2.2 น้ำหนัก — แบบ **slot** (เลือกแล้ว · validator ไม่ต้องเดา)
```
n = |S| (0…8)
n = 0      → พอร์ตก่อน trend = เงินสด 100%
n ≥ 1      → v = wt.risk_parity_weights(funds, wk, vol_map, "erc")             # ERC เต็ม 1 ภายในกองที่มี (n = 1 → [1.0])
             cap_n = min(1.0, 0.25 × 8 / n) ;  u = wt.apply_cap(v, cap_n)       # = เพดาน 25% ของ "พอร์ต" (ไม่ใช่ของ sleeve)
             w_i = (n / 8) · u_i     ;  Σ w = n/8                               # แต่ละ "ช่อง" = 1/8 ของพอร์ต · ช่องว่าง (8 − n)/8 = เงินสด
```
- เหตุผลเลือก slot (ไม่ใช่ ERC เต็ม 100% ในกองที่มี): (1) ผู้ใช้สั่ง "ส่วนที่ขาด = เงินสด" — ERC เต็ม 100% ทำให้ไม่มีส่วนที่ขาด (2) เกณฑ์ 1.0 บอกว่า opportunity set แย่
   → เงินสดตามสัดส่วนช่องว่างคือความหมายของเกณฑ์ (3) ERC เต็ม 100% กับ 1–3 กองขัดเพดาน 25% / concentration · (4) **n = 8 → w = apply_cap(ERC, 0.25) = เดิมพอดี** (regression ตรง)
- ทำไม cap_n: `apply_cap(v, 0.25)` กับ n < 4 เป็นไปไม่ได้ (Σ คืน < 1 เงียบๆ) · cap_n ทำให้เพดานกองละ 25% ของพอร์ตก่อน trend เท่าเดิมทุก n
- ภายในช่องยังเป็น ERC (กองละไม่จำเป็นต้อง = 1/8 พอดี) · "1/8" เป็นงบหุ้นต่อช่องรวม ไม่ใช่เพดานรายกอง

### 2.3 เงินสดรวม + plan
```
T:  c_tr = wt.trend_filter_cash(acwi, t, 0.25)   ;   N:  c_tr = 0
กอง i = (1 − c_tr) · w_i        __CASH__ = 1 − Σ_i (1 − c_tr) · w_i = 1 − (1 − c_tr) · n/8      # ซ้อนแบบคูณ (trend ย่อส่วนหุ้นที่มีอยู่)
```
- ตัวอย่าง: n = 8, trend ติด → หุ้น 75% (= เดิม) · n = 4, trend ติด → หุ้น 37.5% · n = 0 → เงินสด 100% ทั้ง T/N

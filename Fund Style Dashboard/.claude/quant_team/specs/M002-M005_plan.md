## 3. เกณฑ์ตัดสิน (ลงทะเบียนล่วงหน้า)

1. ตัวชี้วัดหลัก = Sharpe ช่วง primary (rf 2%, ต้นทุน 0.5%/ข้าง) ตามนิยาม M001 §5 **ไม่เปลี่ยน** + CI95% block bootstrap (block 3 เดือน, 2,000 รอบ, seed 0)
2. เทียบองค์ประกอบ: ΔSharpe(ลูก − parent) + **CI95% แบบ paired block bootstrap** (สุ่ม index บล็อกชุดเดียวกันกับทั้งสองซีรีส์ แล้วคำนวณผลต่าง)
   — องค์ประกอบ "ช่วย" ถ้า ΔSharpe > 0 · "ช่วยอย่างมีนัย" ถ้า CI ของ Δ ไม่คร่อม 0 (คาดว่าแทบไม่มีตัวไหนถึง เพราะ 45 เดือน)
3. **โมเดลที่จะเสนอ = M005 (#8) ตามที่ลงทะเบียนไว้** ไม่ว่าผลจะเป็นอย่างไร · trial อื่นเป็น ablation
   — ถ้า trial อื่นดีกว่า M005 ให้รายงานตรงๆ แต่ห้ามเปลี่ยนตัวเสนอเอง (ต้องให้ผู้ใช้ตัดสิน และติดป้ายว่าเลือกหลังเห็นผล)
4. "ถึงเป้า" = Sharpe point ≥ 0.95 **และ** รายงานคู่ deflated/CI เสมอ · ถ้าไม่ถึง รายงานค่าจริง + ติดที่อะไร
5. Sanity ที่ต้องผ่านก่อนเชื่อผล: M001 รันซ้ำด้วย simulator ใหม่ได้ตัวเลขเดิมทุกหลัก (C7) · Sharpe ≥ 1.5 ใน trial ใด → ให้สงสัย bug/look-ahead ก่อน

### C1 Universe U_t — `common.universe_at(nav, t)` (เหมือน M001: NAV สด ≤ 90 วัน + ≥ 252 NAVDate ตั้งแต่ 2021-01-01 · ไม่ใช้คอลัมน์ `status`)

### C2 Investable set I_t (ชุดที่คัดได้ — B0 ไม่เปลี่ยน)
เริ่มจาก U_t แล้วตัด/จัดกลุ่มตามลำดับ:
1. **NAV สดสำหรับซื้อ**: `t − last_nav_date ≤ 10` วันปฏิทิน (กันซื้อกองที่หยุดรายงาน — M001 มี cannot_buy เพราะเรื่องนี้) · ตรวจแล้ว: ทุก t ใน primary ผ่าน ≥ 99% ของ U_t
2. **ตัด class สิทธิภาษี** (ลูกค้าทั่วไปสลับออกไม่ได้อิสระ): FundCode มี token (แยกด้วย `-` หรือช่องว่าง) ตรง
   `SSF|SSFX|SSFE|RMF|TESG|THAIESG|THAIESGX` (ไม่สนตัวพิมพ์) — รายงานจำนวนที่ตัด
3. **family key** `fam(f)`:
   - ถ้า f อยู่ใน `base_data/share_class_groups.csv` → ใช้ค่า `group` (ผ่าน `common.load_groups()`)
   - ไม่อยู่ → ตัด token ท้าย (แยกด้วย `-`) ซ้ำได้สูงสุด 2 ครั้ง ถ้า token ตรง regex (ไม่สนตัวพิมพ์)
     `^(A|D|R|RA|RD|A\(A\)|A\(D\)|H|UH|E|P|I|IA|AC|AR|AE|C|X|SSF|SSFX|RMF|TESG|THAIESG|THAIESGX)$` และส่วนที่เหลือไม่ว่าง
     (เช่น `ES-NDQPIN-UH-A` → `ES-NDQPIN` · `KKP TECH-H` → `KKP TECH`)
   - เหตุผล: csv ครอบคลุมแค่ 70 กอง/32 กลุ่ม แต่ตรวจเองพบ 64 base ที่มีหลาย class (133 กอง) และ **70 กองหลาย class ไม่อยู่ใน csv**
     (เช่น `ES-GINFRA-A/-D`, `KKP NDQ100-H/-UH`) → ถ้าไม่จัดกลุ่ม จะถือกองเดียวกันซ้ำ 2 class
   - validator เขียน `results/M002_family_map.csv` (FundCode, family, source=csv|suffix, is_dividend) ให้ reviewer ตรวจ
   - H กับ UH อยู่ family เดียวกัน (พอร์ตหุ้นชุดเดียว ต่างแค่ hedge) → เลือกได้ 1 class ต่อ family
4. **กติกา class ปันผล (-A แทน -D)**: `is_dividend(f)` = token ท้ายตัวใดตัวหนึ่ง (ก่อนตัด) ตรง `D|RD|A\(D\)` ·
   ตัด f ที่ `is_dividend` **ถ้า family นั้นมี class ที่ไม่ใช่ปันผลอยู่ใน I_t** · ถ้ามีแต่ class ปันผล ให้คงไว้ (NAV ต่ำกว่าจริง = conservative) และนับจำนวน
5. ต้องมีสัญญาณครบ (C3) — ไม่ครบ = ไม่อยู่ใน I_t ไตรมาสนั้น (ไม่ประมาณค่าแทน)

### C3 สัญญาณระดับกอง (NAV ≤ t เท่านั้น · ทุก slice ต้อง `assert index.max() <= t`)
- **NAV สิ้นเดือน** P_f(m): ทุก m ใน `common.month_ends(calendar, ...)` ≤ t = NAV ล่าสุดที่ NAVDate ≤ m และ NAVDate ≥ m − 10 วันปฏิทิน, ไม่งั้น NaN
  · M₀ = เดือนของ t (t เป็นวันสิ้นไตรมาส) · M₋k = ย้อนหลัง k เดือน
- **R12_1** = P(M₋₁) / P(M₋₁₂) − 1 (momentum 12-1 ข้ามเดือนล่าสุด — Jegadeesh–Titman 1993) · NaN ถ้าจุดใดขาด
- **NAV รายสัปดาห์**: w_k = วันทำการสุดท้ายของปฏิทินดัชนีในแต่ละสัปดาห์ (ISO week) ที่ ≤ t · 53 จุดล่าสุด → 52 return
  · NAV ของจุด = NAV ล่าสุด NAVDate ≤ w_k และ ≥ w_k − 10 วันปฏิทิน ไม่งั้น NaN · return = pct_change (NaN ถ้าจุดใดขาด)
- **vol52** = std(ddof=1) ของ return รายสัปดาห์ที่ไม่ NaN × √52 · ต้องมี **≥ 40 ค่า** ไม่งั้น NaN
- **stale-price guard**: สัดส่วน return รายสัปดาห์ที่ = 0 พอดี > 20% → NaN (NAV ค้างทำให้ vol ต่ำหลอก) · และ vol52 < 2% → NaN
- **SR12** = (R12_1 − 0.02 × 11/12) / vol52 (Sharpe ย้อนหลังแบบ risk-adjusted momentum — Barroso & Santa-Clara 2015; Daniel & Moskowitz 2016)
- การเรียง: สัญญาณมาก→น้อย · tie → vol52 น้อยก่อน → FundCode ตามตัวอักษร (deterministic)
- ใช้ return รายสัปดาห์ (ไม่ใช่รายวัน) เพราะ NAV กองรายงานไม่ครบทุกวัน (ตรวจเอง: จำนวน NAV ต่อปี median 184–237, p10 174–215)
  และลด bias NAV ต่างเขตเวลา (BRIEF จุดอ่อน #4, #5)

### C4 อันดับระดับ family
- ตัวแทน family = class ใน I_t ที่สัญญาณสูงสุด (ตาม tie rule C3) — **ยกเว้น** family ที่ถืออยู่: ตัวแทน = class ที่ถืออยู่ (ถ้ายังอยู่ใน I_t)
  เพื่อไม่สลับ class ไปมา (H↔UH) · ถ้า class ที่ถือหลุด I_t แต่ family ยังมี class อื่น → ถือว่า "กองที่ถือหลุด" (ขาย) และ family กลับไปแข่งแบบปกติ
- rank(fam) = อันดับของสัญญาณตัวแทนในบรรดา family ทั้งหมดใน I_t (1 = ดีสุด)

### C5 การคัดแบบ hysteresis (พารามิเตอร์ N = จำนวนกองเป้าหมาย, K = อันดับหลุด)
1. H = กองที่ถือจากรอบก่อน (น้ำหนักเป้าหมายรอบก่อน > 0 · ไม่รวมเงินสด) · รอบแรก H = ∅ · ถ้ารอบก่อนเป็น `fallback=b0` → H = ∅
2. **คงไว้**: h ∈ H ที่ยังอยู่ใน I_t และ rank(fam(h)) ≤ K → S = {h เหล่านี้}
3. **เติม**: ไล่ family ตาม rank ที่ยังไม่อยู่ใน S เพิ่มตัวแทนเข้า S จน |S| = N (M005: ข้ามตัวที่ไม่ผ่าน dedupe — ดู M005)
4. |S| < N เพราะ family ไม่พอ → ถือเท่าที่มี · ถ้า |S| < 4 → ใช้น้ำหนัก B0 ไตรมาสนั้น (บันทึก `fallback=b0`; ตรวจแล้ว family ใน primary มี 163–309 จึงไม่ควรเกิด)
5. บันทึกต่อไตรมาส: S, rank ของทุกตัวใน S, จำนวนตัวที่คงไว้/เข้า/ออก
- ค่าหลัก K = 2N (อยู่ใน top 16 จาก ~160–310 family = top ~5–10%) · ตัวเลขนี้มาจากแนวปฏิบัติ buy/hold buffer (Novy-Marx & Velikov 2016) ไม่ได้ tune

### C6 เพดานน้ำหนัก
- ต่อกอง **≤ 25%** ของส่วนหุ้น (N ≥ 4 จึงเป็นไปได้เสมอ) · ใช้แบบ iterative: clip ที่ 25% → กระจายส่วนเกินให้กองที่ไม่ติดเพดานตามสัดส่วน → วนจนไม่มีตัวเกิน (≤ 50 รอบ, tol 1e-12)
- ไม่มี floor · น้ำหนักรวมส่วนหุ้น = 1 − c (c = เงินสด)

### C7 เงินสด (ต้องขยาย `simulate.simulate_path`)
- plan["weights"] ใส่ key พิเศษ `"__CASH__"` = c ∈ [0, 0.25] · Σ(กอง) + c = 1
- simulator ต้อง: (a) **ไม่คิดต้นทุนและไม่นับ turnover** ของขา `__CASH__` (ต้นทุนเกิดเฉพาะขากอง — ขายกองไปถือเงินสด = เสีย 1 ข้าง)
  (b) ไม่บันทึก `cannot_buy` ของ `__CASH__` (c) เงินสดโต rf_annual ด้วย `_grow_cash` เดิม (d) assert money-conservation ยังผ่าน
- ถ้าไม่ทำ (a) โค้ดเดิมจะคิดต้นทุนบนน้ำหนักเงินสดทุกไตรมาสและนับ cannot_buy ผิด
- **regression**: รัน M001 (MS/EW/B0) ซ้ำด้วย simulator ใหม่ → ตัวเลข `M001_summary_metrics.csv` ต้องเท่าเดิม (ไม่นับ trial ใหม่ · status=`regression-check`)
- กองที่ซื้อไม่ได้ → เป็นเงินสดตามกลไกเดิม (อาจทำให้เงินสดรวม > 25% โดยไม่ตั้งใจ) → รายงานจำนวนครั้ง

### C8 Covariance + risk parity (M003+)
- ใช้ return รายสัปดาห์ 52 จุด (C3) ของกองใน S · เอาเฉพาะสัปดาห์ที่ครบทุกกอง (listwise) · ต้องมี ≥ 30 สัปดาห์ ไม่งั้น fallback = inverse-vol (w ∝ 1/vol52) บันทึก `fallback=ivol`
- Σ = `sklearn.covariance.LedoitWolf().fit(X).covariance_ × 52`
- **ERC**: y* = argmin ½ yᵀΣy − Σᵢ (1/N) ln yᵢ (Spinu 2013) ด้วย `scipy.optimize.minimize(method="L-BFGS-B", bounds=[(1e-10, None)]*N, x0=1/vol)`
  · w = y*/Σy* · ตรวจ risk contribution RCᵢ = wᵢ(Σw)ᵢ / wᵀΣw ต่างจาก 1/N ≤ 1e-4 · แล้วใช้ C6
- **HRP** (López de Prado 2016, ตามต้นฉบับ): ρ จาก Σ → d = √(0.5(1−ρ)) → d̃ᵢⱼ = ‖d·ᵢ − d·ⱼ‖₂ → `scipy.cluster.hierarchy.linkage(squareform(d̃), "single")`
  → quasi-diag = `leaves_list` → recursive bisection (แบ่งครึ่งตามลำดับ leaf, น้ำหนักคลัสเตอร์ ∝ 1/variance ของ inverse-variance portfolio ในคลัสเตอร์) → C6
- รายงาน: จำนวนไตรมาสที่ติดเพดาน/ fallback · น้ำหนัก min/max เฉลี่ย

### C9 Vol targeting (M004-VT, M005)
- ใช้น้ำหนักส่วนหุ้น w (Σ=1) ย้อนสร้าง return รายสัปดาห์ของพอร์ต 13 สัปดาห์ล่าสุด ≤ t (สัปดาห์ที่ครบทุกกอง · ถ้า < 10 ใช้ 26 สัปดาห์ · ถ้ายัง < 10 → c_VT = 0 บันทึก)
- σ̂ = std(ddof=1) × √52 · **c_VT = clip(1 − σ*/σ̂, 0, 0.25)** · σ* = 10%/ปี (ใกล้ vol ของ M001-MS 10.7% / B0 12.1% — ตั้งให้ลดความเสี่ยงเฉพาะช่วงผันผวนเกินปกติ)
- หลักฐาน: Moreira & Muir 2017 (vol-managed portfolios); Harvey et al. 2018 (vol targeting ลด left tail ของหุ้น)

### C10 Trend filter (M004-TF, M005)
- A = `msci_index.load_country_index()["MSCI_ACWI"]` (THB) slice ≤ t · SMA200 = ค่าเฉลี่ย 200 จุดสุดท้าย ≤ t (มีพอตั้งแต่ t₁ — ดัชนีเริ่ม 2021-01-01)
- **c_TF = 0.25 ถ้า A_t < SMA200 ไม่งั้น 0** (Faber 2007; Moskowitz–Ooi–Pedersen 2012) · ใช้ดัชนีตลาดภายนอกแทน NAV กอง = ไม่ขึ้นกับรู NAV

# COST — ใช้ค่าธรรมเนียมจริงจาก SecFundFee แทน 0.5%/ข้าง (เปลี่ยนวิธีวัด · ไม่นับ trial)

สถานะ: ผู้ใช้อนุมัติ 2026-10-02 · เขียนโดย supervisor · ผู้รัน: backtest-validator

## ข้อมูล
- `base_data/SecFundFee.csv` (schema: `base_data/FUNDPROFILE_SECFUNDFEE_SCHEMA.pdf` §3) · ใช้ `Complex Type Code = FEEUH` และคอลัมน์
  **`Actual Value`** (อัตราที่เก็บจริง %) ไม่ใช่ `Rate` (เพดาน) · Code: **FF** = front-end (จ่ายตอนซื้อ) · **BF** = back-end (ตอนขาย) ·
  **SI** = สับเปลี่ยนเข้า · **SO** = สับเปลี่ยนออก · ไม่ใช้ CF/TF/OT
- `Fund Code` ตรงกับ FundCode ของ NAV (570/570) · บลจ. จาก `base_data/FundProfile.csv` คอลัมน์ `AMC_CODE`
- **point-in-time**: ณ วันซื้อขาย e ใช้แถวล่าสุดที่ `As of Date ≤ e` · ถ้าไม่มี (ก่อน snapshot แรก ~2023-05) ใช้ snapshot เก่าสุดที่มี
  (ค่าธรรมเนียมแทบไม่เปลี่ยน: 4/93 รายการของกองที่เคยถือ) — ติดป้ายเป็นข้อจำกัด
- ค่าว่าง/ไม่เป็นตัวเลข/ติดลบ → **median ของกอง E** ตาม Code ณ snapshot ล่าสุด (FF 1.5 · BF 0 · SI 1.07 · SO 0 — คำนวณจริงและรายงาน)
- TER/ค่าบริหารกองหักใน NAV แล้ว — ไม่คิดซ้ำ

## สูตรต้นทุนต่อ entry (rebalance หรือ scale) — ใช้กับขากองเท่านั้น · ขา `__CASH__` ไม่มีต้นทุน
ให้ s_i = ยอดขายกอง i (สัดส่วนพอร์ต, Δw<0) · b_j = ยอดซื้อกอง j (Δw>0)
1. แยกตาม บลจ.: ภายใน บลจ. a ให้ m_a = min(Σ s_i, Σ b_j) เป็นยอด "สับเปลี่ยน" ได้
   - ต้นทุนช่องทางสับเปลี่ยน = m_a × (SO เฉลี่ยถ่วงยอดขาย + SI เฉลี่ยถ่วงยอดซื้อ) · ช่องทางขาย-ซื้อ = m_a × (BF เฉลี่ยถ่วง + FF เฉลี่ยถ่วง)
   - ใช้**ช่องทางที่ถูกกว่า** สำหรับ m_a
2. ยอดที่เหลือ (ขายเกิน/ซื้อเกินใน บลจ. นั้น หรือข้าม บลจ.) → ขาย × BF ของกองนั้น · ซื้อ × FF ของกองนั้น
3. ต้นทุนรวมหักจากมูลค่าพอร์ต ณ e แบบเดียวกับ C7 เดิม (กลไกเงินสด/ซื้อไม่ได้ไม่เปลี่ยน)

## 2 กรณีที่ต้องรายงาน
- **(ก) จ่ายเต็ม**: ตามสูตรข้างบน
- **(ข) ยกเว้น front-end**: FF = 0 และ SI = 0 (สมมติผู้จัดจำหน่ายยกเว้นค่าธรรมเนียมขาย/สับเข้า) · BF/SO ตามจริง
- คงรายงานเดิมไว้คู่กัน: ต้นทุนคงที่ 0% และ 0.5%/ข้าง

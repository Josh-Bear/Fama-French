### 2. บั๊ก PY bootstrap (y* รวมค่าคงที่) — **แก้ถูก · ข้อสังเกตเล็กน้อยเรื่อง size**
- โค้ด: `fitted[:, j] = X[:, 1:] @ fit.coef[j][1:]` · `fit_funds` สร้าง X = [1, D] → coef[0] = α → ตัด α ออกถูกต้อง · ทุกกองครบทุกแถว (บังคับด้วย ValueError) ทำให้ ok == mask · ê* ใช้ดัชนีบล็อกชุดเดียวทุกกอง (คง cross-correlation) · s² ใช้ df T − p ตรงกับ t_ols ของข้อมูลจริง · p_boot = (1 + #{J* ≥ J})/(B + 1) ถูก
- test 14 (ค) จำลอง H0 iid 200 ชุด ได้ size ของ p_boot ใน 2–9% → ผ่าน (pytest 48 passed) — ยืนยันว่าบั๊กเดิม (α ติดไปใน y* จะทำให้ J* เลื่อนขึ้นและ p_boot ใหญ่ผิด) ไม่อยู่แล้ว
- ข้อสังเกต (เล็กน้อย m3): บนข้อมูลจริง size05 ของ PY asymptotic ภายใต้ null bootstrap = 1.7–5.1% (median 2.9%) และ p_boot < p ใน 11/12 แถวหลัก = **ทิศตรงข้ามกับความคาดหมาย 8.10** (คาดว่า asymptotic over-reject 6–15%) · สอดคล้องกันภายใน (J* กระจายต่ำกว่า 0 → J จริงอยู่หางขวามากกว่าที่ asymptotic บอก) · กลไกที่เป็นไปได้: fixed-design ตัดความสัมพันธ์ heteroskedasticity–factor ออก · `mean_alpha_star` ปัดเหลือ 0 ทศนิยม 3 ตำแหน่ง (หน่วยรายสัปดาห์) จึงไม่ใช่หลักฐาน — หลักฐานคือโค้ด + test 14
- ผลต่อข้อสรุป: แถวหลัก (test) ของ ①a/①c ทุกแถว p_boot > 0.05 (ต่ำสุด 0.073 ฐาน ①c, 0.084 L2-2, 0.092 L2-3) → **ไม่ปฏิเสธที่ 5% ทั้งสองวิธี** · ที่ 10% สามแถวนี้จะปฏิเสธด้วย p_boot → รายงานต้องไม่เขียนว่า "pricing error ไม่มีนัยแน่นอน" · ตัวเทียบ ③b (0.012) / L2-5 (0.001) ปฏิเสธทั้งสองวิธี
- เสนอ (ไม่บังคับ): บันทึก mean และ quantile ของ J* ใน py.csv รอบหน้า

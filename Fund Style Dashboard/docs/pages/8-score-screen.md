## สูตร

```
mom(i)        = ราคา(t−21) ÷ ราคา(t−252) − 1                       ← momentum 12-1 (config.SCORE_RETURN_COL)
vol(i)        = std(return รายวัน 231 ตัว ช่วงเดียวกัน) × √252     ← realized vol (config.SCORE_VOL_COL)
zone_score(i) = percentile(mom ÷ vol) ภายใน scope → rescale (0.01, 0.99)     ← §12.14 · 2026-09-30
country_sector_score(i,j)= zone_score(country i) × zone_score(sector j) × 100

score(กอง)               = (R² country × R² sector) × country_sector_score(country_primary, sector_primary)
score_secondary(กอง)     = (R² country × R² sector) × country_sector_score(country_secondary, sector_secondary)
```

- **ทำไมข้ามเดือนล่าสุด (momentum 12-1)** — เดือนล่าสุดมักกลับทิศ (short-term reversal) สัญญาณจริงจึงวัดจาก t−252 ถึง t−21
  backtest 55 รอบ × 28 ดัชนี (2026-09-29): IC ของคะแนนโซนต่อ return 63 วันข้างหน้า 0.016 → **0.036** เมื่อข้ามเดือนล่าสุด
- **ทำไมหาร return ด้วย realized vol (แทนสูตรเดิม อันดับ return × อันดับ GARCH)** — สูตรเดิมเอียงไปหาตลาด vol ต่ำ
  (สหสัมพันธ์กับอันดับ vol ต่ำ 0.71 country) จน IC ของ country ติดลบ · dry run 54 รอบระดับดัชนี: IC 0.087 (country) / 0.097 (sector)
  เทียบสูตรเดิม −0.031 / 0.030 · dry run 55 รอบกับ return กองจริง 63 วัน: IC คะแนนกอง 0.132 เทียบ 0.104 · ไม่ใช้ GARCH แล้ว
  (`vol_forecast` ยังอยู่ใน snapshot ให้หน้า 5) · สูตรเดิมเลือกได้ด้วย `SCORE_ZONE_METHOD = "rank_x_rank_garch"` (เก็บไว้ A/B 1 รอบ)
- **ข้อจำกัดของการหาร** — momentum ติดลบ: ตัวที่ vol ต่ำได้ ratio ติดลบมากกว่า (−5%/10% = −0.5 แย่กว่า −10%/40% = −0.25)
  ตอนนี้ติดลบแค่ INDIA (1 จาก 11) · vol ≤ 0 / NaN → คะแนน NaN (กองที่เกาะโซนนั้นไม่ได้คะแนน)
- **ทำไม rescale (0.01, 0.99)** — ตัวอันดับสุดท้ายของ scope จะได้ percentile 0 พอดี แล้วคูณกันทำให้ทั้งแถว/คอลัมน์เป็น 0
- *(สูตรเดิม)* กลับด้าน vol ด้วย `rank(ascending=False)` ไม่ใช่ `1 − rank` — เพราะ `rank(pct=True)` ต่ำสุดคือ 1/n ไม่ใช่ 0
- **R² คูณกัน** เพราะคะแนนโซนเป็น cross term ของทั้งสอง scope อยู่แล้ว — กองที่ match ไม่แน่นด้านใดด้านหนึ่งจะถูกลดคะแนน

## การเลือกแบบไม่ซ้ำการเดิมพัน (greedy)

ไล่จากคะแนนสูงสุดลงมา:
1. ถ้าคู่ **primary** (country, sector) ยังไม่ถูกใช้ **และ** score ≥ `SCORE_MIN_ELIGIBLE` (0.7) → เลือก
2. ไม่งั้น (primary ชน **หรือ** อ่อนกว่าเกณฑ์) ถ้าเปิดโหมด Primary + Secondary, คู่ **secondary** ยังไม่ถูกใช้,
   **secondary ผ่านเกณฑ์ band** (ทิศทางเดียวกับ primary + แรง >= 70% ของ primary ทั้ง country และ sector —
   ดูหัวข้อถัดไป) **และ** score คู่สำรอง ≥ 0.7 → เลือกผ่านคู่สำรอง
3. ไม่งั้นข้าม

เลือกแล้ว **มาร์ค used ทั้ง country และ sector ของคู่ที่ใช้จริงเสมอ** (ทุกโหมด) · โหมด Primary + Secondary มาร์ค
**ทั้งสองคู่ของกองนั้น** (primary + คู่สำรองที่ผ่าน band) ด้วย — กันกองที่ profile เหมือนกันทั้งคู่หลุดเข้ามาทางคู่ที่ยังว่าง
(เคย: KT-MFE-A + PRINCIPAL GEF-A = เดิมพันเดียว · แก้ 2026-10-02)

**share class ของกองเดียวกันผ่านได้ไม่เกิน 1 class** (เพิ่ม 2026-09-30) — กลุ่มอยู่ใน `base_data/share_class_groups.csv`
(32 กลุ่ม · แก้ด้วยมือได้) · class ที่คะแนนสูงสุดผ่านก่อน ตัวอื่นในกลุ่มถูกข้าม · หน้าอื่นยังเห็นทุก class
เหตุผล: share class ถือพอร์ตเดียวกัน (corr รายวัน ~0.99) แต่ ElasticNet อาจให้คู่ country/sector ต่างกัน จึงหลุดตัวกรองคู่ได้
(เช่นโหมด OR ชุด 18 เคยได้ LHUSFIN-A กับ LHUSFIN-D พร้อมกัน)

**เพดานจริงของจำนวนกองที่ผ่านเกณฑ์** (greedy ไล่ได้สูงสุด `SCORE_TOP_N` = 20):

| โหมด | เพดาน | เหตุผล |
|---|---|---|
| AND (ค่าเริ่มต้น) | **≤ 10** | เลือก 1 กอง = ใช้ไป 1 sector · sector มีแค่ 10 ตัว |
| OR | ≤ country + sector − 1 (20 clean / 27 all) | แต่ละกองต้องเพิ่มของใหม่อย่างน้อย 1 ตัว — กองแรกใช้ไป 2 |

ตัวเลขจริงก่อนเกณฑ์ 0.7: OR ได้ 15 กอง (clean) / ชนเพดาน 20 (all) · `greedy_select` เติมแถวที่เหลือด้วยกองคะแนนถัดไป
(`pair = fill`, eligible = False) แต่**หน้าเว็บแสดงเฉพาะกองที่ผ่านเกณฑ์** ไม่เกิน `PORTFOLIO_TOP_N` = 5 แถว

**ลำดับการไล่ = score ของคู่ primary เสมอ** (ยืนยัน 2026-09-29) — กองที่ primary อ่อนแต่คู่สำรองแรง (เช่น PRINCIPAL GEF-A
primary 1.61 · คู่สำรอง 8.01) จะถูกพิจารณาช้า ถ้าเรียงด้วย max(score, คู่สำรอง) Top 5 โหมด OR จะเปลี่ยน แต่เสี่ยงได้ share class
ของกองเดียวกันคู่กัน (GEF-A + GEF-X) จึงไม่ทำ

**Band filter ของ secondary (แก้แล้ว 2026-09-29)**: เดิม secondary = "อันดับ 2 ของ |coefficient|" เฉยๆ
ไม่มีเกณฑ์ขั้นต่ำ ทำให้บางกอง secondary จริงๆสวนทาง primary (คนละเครื่องหมาย, เช่น TUSFIN-A) หรืออ่อนมาก
(เช่น ONE-APACESG 4.76 vs 0.37) แต่ก็ยังถูกใช้เป็น fallback ได้ — ตอนนี้เพิ่มเกณฑ์: secondary_coef ต้องอยู่ใน
`[primary_coef × (1 − SCORE_SECONDARY_BAND_PCT), primary_coef]` (ทิศทางเดียวกับ primary + แรง >= 70%)
ทั้ง country **และ** sector ถึงจะใช้เป็น fallback ได้ ไม่ผ่าน → `score_secondary` เป็น NaN และกองนั้น
ใช้คู่นี้กระจายความเสี่ยงไม่ได้เลย (ต่างจาก `SECONDARY_BAND_PCT` ของหน้า 5/6 ที่เช็คแบบ |coef| ไม่สนทิศทาง)

## ส่วนที่ 3 — Efficient frontier

### Risk model (Σ)

```
Σ = B · F · Bᵀ + D          (N กอง × N กอง · annualized)
  B = exposure ของกองต่อ factor — joint refit ครั้งเดียวกับ [country ตาม toggle + sector 10]
      (11+10 = 21 หรือ 18+10 = 28 factor) แล้ว unstandardize ให้เป็น beta หน่วยจริง
  F = covariance ของ factor รายวัน · shrinkage Ledoit-Wolf แบบ constant correlation · × 252
  D = (1 − R²) × variance รวมของกอง (idiosyncratic)
```

- **หน้าต่าง rolling 3 ปี** (`PORTFOLIO_LOOKBACK_DAYS = 756`) ทั้ง B, F และ vol — สะท้อน regime ปัจจุบัน
  (ต่างจาก `ann_return`/`ann_vol` ที่แสดงทั่ว dashboard ซึ่งใช้ข้อมูลทั้งช่วง)
- **D = variance ของ return กองต่อจุด NAV × จำนวนจุดต่อปีจริง × (1 − R²)** (แก้ 2026-10-02 จาก × 252) · ใช้ return winsorize ชุดเดียวกับที่ได้ R²
- **fit สดต่อครั้ง ไม่ cache ลงดิสก์** — Σ ผูกกับ "หน้าต่างล่าสุด ณ วันคำนวณ" cache จะเก่าทันทีที่ข้อมูลขยับ
  · fit 4-5 กองใช้ ~2.4-2.6 วินาที (ส่วนใหญ่คือโหลด NAV) · `@st.cache_data` กันไม่ให้คำนวณซ้ำระหว่าง rerun
  · ถ้า fit กองใดล้ม หน้าจะแจ้ง error แต่ยังโชว์ตารางส่วนที่ 2 แล้วหยุดก่อนส่วนที่ 3
- **factor set ต้องตรงกับ toggle** ที่ใช้คัดกอง ไม่งั้น exposure กับเหตุผลที่เลือกกองมาจากคนละชุด
- ⚠️ **√diag(Σ) ไม่เท่ากับ vol จริงของกอง** (ตรวจ 2026-09-29, โหมดเริ่มต้น): KT-MFE-A 11.3% vs 13.5% · PRINCIPAL GEF-X 12.1 vs 12.5 ·
  KT-JPFUND-A 24.1 vs 24.3 · K-AEC 9.5 vs 9.9 — (ตัวเลขก่อนแก้) D คิดจาก return ที่ winsorize แล้ว × 252 ทั้งที่ NAV ไม่ได้มีทุกวัน → แก้ตัวคูณแล้ว 2026-10-02
  ส่วน BFBᵀ มาจาก F รายวันของดัชนี จึงเป็นคนละฐาน · ตาราง Part 2 แยกคอลัมน์ "vol 3 ปี" (จริง) กับ Part 3 "vol (โมเดล)" ไว้ให้เห็น
  (ตัวคูณของ D แก้แล้ว 2026-10-02 · F รายวันคนละฐานกับ D ยังไม่แก้ — ดูข้อควรระวัง 9)

### ผลตอบแทนคาดหวัง (μ) — Black-Litterman implied return

```
Π = γ · Σ_sys · w_ref      γ = 2.5 คงที่ (PORTFOLIO_GAMMA)
Σ_sys = B·F·Bᵀ            (ไม่รวม D — ความเสี่ยงเฉพาะตัว)
w_ref = น้ำหนักเท่ากัน 1/N  (PORTFOLIO_REF_WEIGHT = "equal" · สลับเป็น "aum" ได้ = สัดส่วน AUM cap 50%)
```

- **ไม่ใช้ historical mean return** เพราะ `ann_return` เป็นผลอดีต (CAGR) ไม่ใช่ค่าพยากรณ์
- **γ คงที่ ไม่ถอดจากตลาด** — γ ที่คำนวณจาก realized market return ช่วงสั้นพลิกเครื่องหมายได้
  (ปีที่ตลาดติดลบ → Π ติดลบทั้งกระดาน) · ใช้ค่าคงที่แล้วยังตัดความจำเป็นต้องหา risk-free rate ไทยทิ้งไปด้วย
- **ข้อจำกัดที่ต้องรู้**: Π ไม่มีสัญญาณจากคะแนนโซนอยู่เลย — เหตุผลที่กองถูกเลือกไม่ได้ไหลเข้าสู่การจัดน้ำหนัก
  ถ้าต้องการให้ไหลต่อ ต้องใส่คะแนนเป็น BL **views** (P/Q/Ω) ซึ่งยังไม่ได้ทำ

### หาเส้นด้วย grid enumeration (ไม่ใช้ solver)

1. น้ำหนักแต่ละกองเป็นจำนวนเต็ม % ระหว่าง min ถึง max (ค่าเริ่มต้น 5%-40% ทีละ 1% · ปรับได้ใน UI)
   step เลือกได้เฉพาะค่าที่หาร 100 ลงตัว (`PORTFOLIO_STEP_CHOICES` = 1/2/4/5/10/20/25%) · min/max ที่ไม่ลงตัวกับ step ปัดเข้าในช่วง
   (เดิม step 3% ได้หน่วยละ 3.03% และ step 7% ได้น้ำหนักหลุด min/max — แก้ 2026-09-29)
2. enumerate ทุก combination ที่รวมได้ 100% พอดี — ที่ 5%-40%: 3 กอง **231** · 4 กอง **28,011** · 5 กอง **885,801** ชุด
   (ที่เพดานเดิม 30% 5 กองได้ 213,876 — ตรวจด้วย inclusion-exclusion แล้ว)
3. คำนวณ `risk = √(wᵀΣw)` และ `return = Πᵀw` ทุกชุดแบบ vectorized
4. เก็บเฉพาะจุดที่ไม่มีพอร์ตอื่นให้ return สูงกว่าที่ risk เท่ากันหรือต่ำกว่า = **Pareto frontier**

ข้อดีเทียบกับ `scipy.optimize`: ไม่มีปัญหา convergence · น้ำหนักซื้อขายได้จริง · เห็นพื้นที่ที่เป็นไปได้ทั้งหมดไม่ใช่แค่เส้น
**วัดจริง**: 4 กอง enumerate + คำนวณ + Pareto 0.01 วินาที (frontier 1,631 จุด) · 5 กอง ~0.3 วินาที

**จำนวนกองขั้นต่ำ = 3** (`PORTFOLIO_MIN_FUNDS`) — 2 กองที่เพดาน 40% รวมได้แค่ 80% ไม่ถึง 100% จึงไม่มีพอร์ตที่เป็นไปได้
น้อยกว่า 3 หน้าจะเตือนแล้วไม่คำนวณส่วนที่ 3

| จุด | ความหมาย |
|---|---|

  ส่วนต่างที่เห็นมาจาก D เท่านั้น (frontier ใช้ Σ เต็ม) → กองที่ D สูงถูกลดน้ำหนักลงเล็กน้อย · frontier จึงบอก "ความเสี่ยง
  ที่เลือกรับได้" มากกว่าบอกว่ากองไหนดีกว่า จนกว่าจะใส่ BL views
